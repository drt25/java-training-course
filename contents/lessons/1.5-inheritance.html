Encapsulation

Private data. Getter to read. Setter to change.

What: the field stays inside the class. Why: anyone can write age = -100 if the field is open. Benefit: protect, check, hide the inside. 1.4 used a wallet. Today the same idea is name on Animal.

private String name;

public String getName() {
    return name;
}

public void setName(String name) {
    if (name != null && !name.isEmpty()) {
        this.name = name;
    }
}

Flow

Outside world → getter / setter → private field. Empty name is rejected.

Inheritance

A child class gets the parent’s features

What: Dog can use eat and sleep without writing them again. Why: Dog and Cat both eat and sleep. Copy-paste is easy to break. Benefit: write once, fix once. This is an is-a link: Dog is an Animal. (1.4 was has-a: Student has an Address.)

Without inheritance

Dog and Cat each copy name, eat(), sleep().

With inheritance

Animal holds the common parts. Dog adds bark. Cat adds meow.

Polymorphism

One word. Many forms.

Poly = many. Morph = forms. What: the same call sound() can mean bark or meow. Why: you do not want a new button for every animal. Benefit: one Animal remote, Dog or Cat box. The real object decides what runs.

The remote

Animal a — the type we talk to.

The box

new Dog() or new Cat() — the real object.

The call

a.sound() — Dog barks. Cat meows.

Abstraction

Show the job. Hide the how.

What: Animal says “you must have a sound” without writing a generic sound. Why: you never create a bare Animal at the zoo. Benefit: common eat() stays in Animal. Each child fills sound(). Interface later: what the object can do (swim), not only what it is.

Abstract class

What it is. Dog is an Animal. Shared fields plus a hole.

Interface

What it can do. Dog can swim. Dog can run.

Inheritance in code

extends means Dog already has eat and sleep

Dog does not write eat(). It still works because class Dog extends Animal.

class Dog extends Animal {
    void bark() {
        System.out.println("Dog is barking");
    }
}

Dog dog = new Dog();
dog.setName("Tommy");
dog.eat();
dog.bark();
Animal is eating Dog is barking

Remember

Common code lives in Animal. Dog only adds what is new.

Types in Java

Four shapes. A class cannot have two parents.

Multiple inheritance through two classes is not allowed. Two interfaces later — that is allowed.

Single

One parent, one child. Animal → Dog.

Multilevel

Parent → child → grandchild. Animal → Mammal → Dog.

Hierarchical

One parent, many children. Animal → Dog and Cat.

Multiple

Not with classes. class Robot extends Animal, Machine will not compile.

Overloading

Same method name. Different parameters.

1.3b already showed this. Java picks the method when you compile, by what you pass in. Memory: same name, different parameters.

int add(int a, int b) {
    return a + b;
}

int add(int a, int b, int c) {
    return a + b + c;
}

add(10, 20);
add(10, 20, 30);

Compile time

This is static polymorphism. Changing only the return type is not enough.

Overriding

The child changes the parent’s method

Same name. Same parameters. Dog and Cat each write their own sound(). Java picks the method when you run, from the real object.

class Dog extends Animal {
    void sound() {
        System.out.println("Dog barks");
    }
}

Dog dog = new Dog();
dog.sound();
Dog barks

Surface rule

Parent has sound(). Child writes sound() again. The child’s version runs.

Overloading = same name, different parameters. Overriding = child changes the parent’s behavior.

super

super talks to the parent. this talks to me.

1.4: this is the current object. Today: super is the parent. super(...) must be the first line in a constructor.

Parent field

super.name — the parent’s name, not the child’s.

Parent method

super.eat() — run Animal’s eat, then add Dog’s extra line.

Parent constructor

super(name) — set the name in Animal first.

Lab: SuperDemo.java

final

final means you cannot change it further

Three places. Same word. Three locks.

Variable

final int MAX_AGE = 100; — you cannot assign 200 later.

Method

final void breathe() — Dog cannot override breathe. Every animal breathes the same way.

Class

String is final. You cannot write class MyString extends String.

Lab: FinalDemo.java

Dynamic polymorphism

The variable says Animal. The object is a Dog.

At run time Java looks at the real object and calls Dog’s sound(). That is overriding + a parent-type variable.

Animal a = new Dog();
a.sound();
Dog barks

Read the line

Left: reference type Animal. Right: real object Dog. The call uses the object.

Static polymorphism

Overloading is decided when you compile

Same word “polymorphism.” Two times. Easy pair to remember.

Static · compile

Overloading. add(10, 20) vs add(10, 20, 30).

Dynamic · run

Overriding. Animal a = new Dog(); a.sound();

Lab: PolyAnimal.java

Abstract class

A base class with a hole the child must fill

You cannot new Animal() if Animal is abstract. Common eat() stays. sound() has no body. Dog and Cat must write it. Simple idea: common work + rules for children.

abstract class Animal {
    abstract void sound();

    void eat() {
        System.out.println("Eating");
    }
}

Allowed

Animal dog = new Dog(); — not new Animal().

Lab: AbstractAnimal.java

Interface

A contract. If you implement me, you must swim.

An interface is not a parent family. It is a skill. A class can implement more than one interface. That is how Java does multiple inheritance of behavior.

interface Swimmable {
    void swim();
}

class Dog implements Swimmable {
    public void swim() {
        System.out.println("Dog swims");
    }
}

Can do

Dog is an Animal (class). Dog can swim (interface). Fish can swim too — not the same family.

Lab: CanSwim.java

Abstract vs interface

Is-a versus can-do

No holy war. Pick the one that matches the sentence you would say in English.

Abstract class

What the object is. Dog is an Animal. Shared name and eat(). A hole for sound().

Interface

What the object can do. Dog can swim. Dog can run. Many unrelated classes can sign the same contract.

Object

If you write no extends, you still extend Object

Object is the root. Printing an object without toString looks like an address — same idea as a raw array in 1.3b. Override toString so the console says Tommy.

public String toString() {
    return getName();
}

System.out.println(dog);
