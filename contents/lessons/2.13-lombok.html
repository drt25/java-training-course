Less code

Lombok writes the methods you repeat on every class.

Project Lombok is a Java library that reduces boilerplate. Boilerplate is the repetitive code developers write again and again.

Same class

The short class still has the methods.

Written by hand
public class Student {
    private Long id;
    private String name;
    private String email;

    public Student() { }

    public Student(Long id, String name, String email) {
        this.id = id;
        this.name = name;
        this.email = email;
    }

    public String getName() { return name; }
    public void setName(String name) {
        this.name = name;
    }
    // id and email need the same pair
}
With Lombok
import lombok.Data;
import lombok.NoArgsConstructor;
import lombok.AllArgsConstructor;

@Data
@NoArgsConstructor
@AllArgsConstructor
public class Student {
    private Long id;
    private String name;
    private String email;
}

The compiler sees getters, setters, both constructors, toString, equals, and hashCode on the right-hand class as well.

Annotations

Eight annotations cover a beginner project.

@Getter

Generates getter methods.

@Setter

Generates setter methods.

@ToString

Generates toString().

@NoArgsConstructor

A constructor with no parameters.

@AllArgsConstructor

A constructor with every field.

@RequiredArgsConstructor

A constructor for required fields.

@Data

Getters, setters, toString, equals, and hashCode.

@Builder

A builder for creating the object.

Getters and setters

Two annotations replace four methods.

Student
@Getter
@Setter
public class Student {
    private String name;
    private String email;
}

getName()

Returns the name.

setName()

Stores a new name.

getEmail()

Returns the email.

setEmail()

Stores a new email.

Constructors

One annotation for each constructor you used to write.

Student
@NoArgsConstructor
@AllArgsConstructor
public class Student {
    private Long id;
    private String name;
}
Calls
Student student1 = new Student();

Student student2 =
        new Student(1L, "Ram");

@RequiredArgsConstructor builds a constructor for final fields, such as a repository in a service. This project still writes that service constructor by hand.

Builder

Name the fields. Skip the parameter order.

Student
@Builder
public class Student {
    private Long id;
    private String name;
    private String email;
}
Create
Student student = Student.builder()
        .id(1L)
        .name("Ram")
        .email("ram@example.com")
        .build();

Each call names the field it sets. The reader can see that Ram is the name.

pom.xml

Spring Boot already knows the Lombok version.

pom.xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <optional>true</optional>
</dependency>

Leave the version off. The Spring Boot parent supplies it. Lombok runs while the code compiles. In the IDE, turn on annotation processing, and install the Lombok plugin where that IDE asks for one.

Student entity

The REST entity keeps its fields. Lombok writes the methods.

Student.java
package com.example.studentmanagement.entity;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import lombok.AllArgsConstructor;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

@Entity
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private String email;
}

Replace the handwritten getters, setters, and empty constructor in coding/2.12/student-api. JPA still needs the no-argument constructor. Jackson and the service still call the getters and setters.
