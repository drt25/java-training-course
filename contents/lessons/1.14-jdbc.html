Student app

A Student Management System has to remember people.

Name, age, address, phone, course, email. While the program runs, Java can keep those in variables.

In memory

The problem

Close the program and those variables disappear with it.

The student is still a real person. The program no longer has the data.

Persistent data

We need data that is still there tomorrow.

Applications must store information outside RAM so it survives a restart.

Persistent data is data that remains available even after the application is closed.

Variables

Live in memory. Gone when the program ends.

Storage

Lives on disk. Still there when you open the app again.

Statement

A Statement is the object that sends SQL.

After you have a connection, you ask it for a statement. Then you run a SQL string.

Statement stmt = con.createStatement();

stmt.executeUpdate("...");
stmt.executeQuery("...");

Remember

Connection → Statement → SQL. We use Statement today. Not PreparedStatement.

Two methods

Change data with executeUpdate. Read data with executeQuery.

Pick the method from the kind of SQL. Mixing them up is a common first error.

executeUpdate

CREATE, INSERT, UPDATE, DELETE

Returns how many rows changed. No result table.

executeQuery

SELECT — view rows

Returns a ResultSet. Walk it with next().

SELECT

View rows with executeQuery and ResultSet.

rs.next() moves to the next row. Then read each column by name.

ResultSet rs = stmt.executeQuery(
        "SELECT * FROM student");

while (rs.next()) {
    System.out.println(
            rs.getInt("id") + " "
            + rs.getString("name") + " "
            + rs.getString("address") + " "
            + rs.getInt("roll_no"));
}

Remember

getInt for numbers. getString for text. Column names match the table.

Lab: ViewStudents.java

UPDATE

Change Ram’s address. Leave the other rows alone.

WHERE id = 1 picks the row. Without WHERE, every row would change.

stmt.executeUpdate(
    "UPDATE student SET address = 'Lalitpur' WHERE id = 1");
