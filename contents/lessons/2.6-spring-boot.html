Dependency injection

The service receives the repository.

Dependency injection means providing an object that a class needs, instead of making that class create the object itself.
Creates it
public class StudentService {
    private StudentRepository repository =
            new StudentRepository();
}
Receives it
public class StudentService {
    private final StudentRepository repository;

    public StudentService(StudentRepository repository) {
        this.repository = repository;
    }
}

Three words

Dependency, injection, and the reason it helps.

Dependency

The object a class needs

StudentService needs a StudentRepository.

Injection

Providing that object

Spring passes the repository into the service.

Benefit

Easier to change

The service can be tested and swapped without rewriting it.

IoC

Spring creates the objects and hands them over.

Instead of creating every object yourself, you ask Spring to manage the objects and provide the ones your class needs.

Principle

IoC

Inversion of Control. Spring takes responsibility for creating and connecting objects.

Place

IoC container

The Spring-managed environment that creates and keeps those objects.

Object

Bean

An object managed by Spring.

Door

ApplicationContext

A container you can ask for a bean and other application services.

DI is the technique of supplying dependencies. IoC is the broader principle. ApplicationContext is how you reach the beans.

A bean

Mark the class, then ask the container for it.

GreetingService
@Component
public class GreetingService {
    public void greet() {
        System.out.println("Hello Students!");
    }
}
DemoApplication
ApplicationContext context =
        SpringApplication.run(
                DemoApplication.class, args);

GreetingService service =
        context.getBean(GreetingService.class);

service.greet();

@Component makes the class eligible for component scanning. getBean returns the instance Spring created.

Constructor injection

A required repository comes through the constructor.

StudentService
@Service
public class StudentService {
    private final StudentRepository repository;

    public StudentService(
            StudentRepository repository) {
        this.repository = repository;
    }
}

final

The repository is set once, when the service is created.

One constructor

Spring calls it and passes the repository. @Autowired can stay off.

Best default

Use this for a dependency the service always needs.

@RequiredArgsConstructor

Lombok can write that constructor.

Written by hand
@Service
public class StudentService {
    private final StudentRepository repository;

    public StudentService(
            StudentRepository repository) {
        this.repository = repository;
    }
}
ReportService
@Service
@RequiredArgsConstructor
public class ReportService {
    private final StudentRepository repository;

    public int count() {
        return repository.findAll().size();
    }
}

@RequiredArgsConstructor generates a constructor for every final field. Spring still calls that constructor. The project needs Lombok.

Service

The service is the same idea as Stage 1.

StudentService
@Service
public class StudentService {
    private final StudentRepository repository;

    public StudentService(StudentRepository repository) {
        this.repository = repository;
    }

    public List<Student> getAllStudents() {
        return repository.findAll();
    }

    public Student saveStudent(Student student) {
        return repository.save(student);
    }

    public void deleteStudent(Long id) {
        repository.deleteById(id);
    }
}

@Service makes this a bean. The constructor receives the repository. getStudent uses findById and throws a simple exception when the id is missing.

Controller

List the students, then save a new one.

StudentController
@Controller
@RequestMapping("/students")
public class StudentController {
    private final StudentService service;

    public StudentController(StudentService service) {
        this.service = service;
    }

    @GetMapping
    public String listStudents(Model model) {
        model.addAttribute("students", service.getAllStudents());
        return "students";
    }

    @PostMapping
    public String saveStudent(@ModelAttribute Student student) {
        service.saveStudent(student);
        return "redirect:/students";
    }
}

@Controller

Returns a view name, such as students.

@GetMapping

Handles the browser opening the list.

Model

Carries the list to the HTML page.

@ModelAttribute

Fills a Student from the form.

redirect

Sends the browser back to the list after a save.

GET /students/new puts an empty student on the form. That method is in the lab file with the rest of the controller.

Edit and delete

The id comes from the URL.

StudentController
@GetMapping("/edit/{id}")
public String editStudent(@PathVariable Long id, Model model) {
    model.addAttribute("student", service.getStudent(id));
    return "student-form";
}

@PostMapping("/{id}/update")
public String updateStudent(@PathVariable Long id,
        @ModelAttribute Student student) {
    student.setId(id);
    service.saveStudent(student);
    return "redirect:/students";
}

@PostMapping("/{id}/delete")
public String deleteStudent(@PathVariable Long id) {
    service.deleteStudent(id);
    return "redirect:/students";
}

@PathVariable

Reads 5 from /students/edit/5.

setId

The URL chooses the id, so the form cannot switch it.

POST delete

The delete button submits a form. The browser does not send DELETE.

Two controllers

A controller can return a page or data.

This project

@Controller

Returns a view name. Thymeleaf renders students.html.

Later

@RestController

Writes the response body, often JSON, straight back to the client.

@Service is the business class. @Repository marks the repository, and Spring Data builds it. @Component is the general marker. @Autowired is unnecessary on the controller’s only constructor.

students.html

The list page loops over students.

templates/students.html
<tr th:each="student : ${students}">
    <td th:text="${student.name}"></td>
    <td th:text="${student.email}"></td>
    <td>
        <a th:href="@{/students/edit/{id}(id=${student.id})}">
            Edit
        </a>
        <form th:action="@{/students/{id}/delete(id=${student.id})}"
              method="post">
            <button type="submit">Delete</button>
        </form>
    </td>
</tr>

th:each

Loops through the students on the model.

th:text

Prints a value into the cell.

th:href

Builds the edit link, including the id.

th:action

Sets the delete form’s address.

student-form.html

One form adds a student and edits a student.

templates/student-form.html
<form th:action="${student.id == null}
        ? @{/students}
        : @{/students/{id}/update(id=${student.id})}"
      th:object="${student}" method="post">

    <label>Name</label>
    <input type="text" th:field="*{name}" required>

    <label>Email</label>
    <input type="email" th:field="*{email}" required>

    <button type="submit">Save Student</button>
</form>

th:object

Connects the form to the student on the model.

th:field

Binds an input to name or email.

th:action

A new student posts to /students. An existing student posts to the update address.

required

The browser asks for a value before it submits.

Thymeleaf is why the project needs that dependency in addition to Spring Web.
