A check that runs itself

JUnit tests a method before a user ever calls it.

JUnit is a Java framework that runs your checks and reports which ones pass or fail.

The code

Two methods. Two tests.

Calculator.java
public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }

    public int subtract(int a, int b) {
        return a - b;
    }
}
CalculatorTest.java
@Test
void testAddition() {
    Calculator calculator = new Calculator();
    int result = calculator.add(10, 20);
    assertEquals(30, result);
}

@Test
void testSubtraction() {
    Calculator calculator = new Calculator();
    int result = calculator.subtract(20, 10);
    assertEquals(10, result);
}

assertEquals(30, result) puts the expected number first and the actual number second.

The pieces

Four lines do the whole check.

CodeMeaning
@TestMarks the method as a test.
new Calculator()Creates the object the test will call.
calculator.add(10, 20)Runs the method under test.
assertEquals(30, result)Passes when result is 30. Fails when it is any other number.

Two folders

The class lives in main. The test lives in test.

src/main/java

Calculator.java

The methods the application uses.

src/test/java

CalculatorTest.java

The checks. They are not part of the running application.

Keep the same package in both folders, com.example.calculator.

Spring Boot

A Spring Boot project already has a place for these tests.

pom.xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>

That starter includes JUnit. Run the tests from the IDE, or with mvn test. Today's lab is ordinary Java plus JUnit, so you can see the test before Spring joins in.
