What is an exception

A problem that happens while the program is running

Java does not know what you want. Without handling, the program stops. Real life: Ram wants Rs. 1000. Balance is Rs. 500. Show an error. Do not crash the app.

int result = 10 / 0;
ArithmeticException: / by zero

Remember

This is not a compile error. The file compiles. It fails when that line runs.

Common exceptions

Know why they happen. Do not memorize a list.

ArithmeticException

10 / 0 — you cannot divide by zero.

ArrayIndexOutOfBounds

numbers[5] on a list of three rooms. Room 5 does not exist.

NullPointerException

name.length() when name is null. There is no String yet.

NumberFormatException

Integer.parseInt("abc") — that text is not a number.

try / catch

Catch the problem. Then the program continues.

try = the risky line. catch = what to do if it fails.

try {
    int result = 10 / 0;
    System.out.println(result);
} catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero.");
}
System.out.println("Program continues...");
Cannot divide by zero. Program continues...

Why

The app can show a message and keep going. Lab: DivideByZero.java

Multiple catch

Specific first. General last.

Exception can catch many types. If you put it first, the specific catch never runs.

try {
    System.out.println(numbers[5]);
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Invalid array index.");
} catch (Exception e) {
    System.out.println("Something went wrong.");
}

Order

Child type first. Parent Exception last.

finally

This block always runs

Exception or no exception. Use it for cleanup. try = try · catch = handle · finally = cleanup.

try {
    System.out.println("Trying...");
} catch (Exception e) {
    System.out.println("Error occurred.");
} finally {
    System.out.println("This always executes.");
}
Trying... This always executes.

Always

Even if catch runs, finally still runs.

throw

I want to throw an exception right here

The method decides: this is not allowed. Stop and tell the caller.

if (amount > balance) {
    throw new IllegalArgumentException(
        "Insufficient balance."
    );
}

Memory

throw actually throws. You create the exception object and send it.

throws

A warning on the method. Not the throw itself.

throws sits on the method line. It tells the caller: this method may produce this exception.

throw

Inside the body. Actually throws an exception.

throws

On the method. Declares that it may throw.

void withdraw(double amount) throws InsufficientBalanceException

Checked vs unchecked

Does Java force you to handle it?

Surface only. Do not go deep today.

Checked

Java checks. You must try/catch or write throws. Example: IOException.

Unchecked

Children of RuntimeException. Java does not force you. Example: divide by zero, null, bad index, parseInt.
