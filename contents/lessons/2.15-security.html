BCrypt

Encode once. Match later. Leave the hash as-is.

Encode
PasswordEncoder encoder =
        new BCryptPasswordEncoder();

String encoded =
        encoder.encode("john123");
Match
boolean matches = encoder.matches(
        "john123",
        encoded
);

The stored value looks like $2a$10$... and includes a random salt. BCrypt is a one-way hash. Login calls matches. It does not turn the hash back into john123.

User

Email is unique. The password column stores the hash.

User
@Entity
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;

    @Column(unique = true, nullable = false)
    private String email;

    @Column(nullable = false)
    private String password;
}

UserRepository extends JpaRepository<User, Long> and adds Optional<User> findByEmail(String email). Spring Data writes that query.

The request

The JSON carries name, email, and password. The id stays in the database.

RegisterRequest
public class RegisterRequest {
    @NotBlank
    private String name;

    @NotBlank
    @Email
    private String email;

    @NotBlank
    private String password;
}

This object is a DTO. It moves data from Postman into the app and leaves database fields such as id out of the request. @Valid runs these checks.

The encoder bean

One BCrypt encoder is shared by registration and login.

SecurityConfig
@Configuration
public class SecurityConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

@Configuration marks the class. @Bean puts the encoder in the Spring container so other classes can receive it.

Register

Save the hash. Keep the typed password out of MySQL.

AuthService
if (userRepository.findByEmail(request.getEmail()).isPresent()) {
    throw new EmailAlreadyRegisteredException();
}
User user = new User();
user.setName(request.getName());
user.setEmail(request.getEmail());
user.setPassword(passwordEncoder.encode(request.getPassword()));
return userRepository.save(user);

A repeated email throws EmailAlreadyRegisteredException. That exception is marked 409 Conflict, the same idea as the student-not-found exception.

The open API

POST /api/auth/register creates the account.

AuthController
@PostMapping("/register")
public ResponseEntity<String> register(
        @Valid @RequestBody RegisterRequest request) {
    authService.register(request);
    return ResponseEntity
            .status(HttpStatus.CREATED)
            .body("User registered successfully");
}

Finding the user

UserDetailsService loads the account by email.

SecurityConfig
return email -> {
    User user = userRepository.findByEmail(email)
            .orElseThrow(() -> new UsernameNotFoundException("User not found"));
    return User.withUsername(user.getEmail())
            .password(user.getPassword())
            .roles("USER")
            .build();
};

Spring Security calls this during login. The username is the email. The password is the stored BCrypt hash. roles("USER") gives the account the USER role.

The rules

Open the register path. Ask for Basic Auth everywhere else.

SecurityFilterChain
http.csrf(csrf -> csrf.disable())
    .authorizeHttpRequests(auth -> auth
        .requestMatchers("/api/auth/register").permitAll()
        .anyRequest().authenticated())
    .httpBasic(Customizer.withDefaults())
    .sessionManagement(session -> session.sessionCreationPolicy(
            SessionCreationPolicy.STATELESS));

permitAll leaves registration open. authenticated requires a valid login. httpBasic reads the Authorization header. STATELESS skips the login session. CSRF is off for this header-based API. Turn it back on for an app that uses browser cookies.
