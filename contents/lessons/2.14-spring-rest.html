API

An API is how two programs talk.

An API, an Application Programming Interface, lets one program ask another program for something and get an answer back.

REST

The URL names the student. The method names the action.

REST means Representational State Transfer. A REST API uses ordinary web addresses and HTTP methods to work with resources such as a student.

Address

URL

/api/students is the collection. /api/students/1 is one student.

Action

HTTP method

GET reads. POST adds. PUT updates. DELETE removes.

Data

JSON

The request and the response carry the student as text.

Result

Status code

200, 201, 204, or 404 says what happened.

Each request stands on its own. The server does not remember a previous click in order to understand this one.

The first looks for welcome.html. The second writes the sentence into the HTTP response. @RestController is @Controller plus @ResponseBody.

Controller
@PostMapping
public Student createStudent(

Spring fills name and email from the JSON, then passes that object into the method.

@ResponseBody

The returned Student is written as JSON.

With @Controller
@Controller
public class StudentApiController {

    @ResponseBody
    @GetMapping("/api/student")
    public Student getStudent() {
        Student student = new Student();
        student.setName("Sita");
        student.setEmail("sita@example.com");
        return student;
    }
}

@ResponseBody tells Spring to write the return value into the response. With @RestController, every handler method already does that.

Mappings

Four annotations, four HTTP methods.

Read

@GetMapping

GET /api/students and GET /api/students/{id}.

Create

@PostMapping

POST /api/students with a JSON body.

Update

@PutMapping

PUT /api/students/{id} replaces the name and email.

Delete

@DeleteMapping

DELETE /api/students/{id} removes that student.

@RequestMapping("/api/students") is the shared prefix. @PathVariable reads the id from the URL.

Methods

Repeating a read, update, or delete does not add a second student.

Read

GET

Returns the student. Calling it again returns the same student.

Create

POST

Adds a student. Calling it again can add another one.

Replace

PUT

Sets the name and email of a known id.

Remove

DELETE

Removes that id. A second call still refers to the same student.

PATCH is a partial update. This project uses PUT for the whole name and email.

Status codes

Five codes cover this classroom API.

200

OK

The read or update succeeded.

201

Created

POST saved a new student.

204

No Content

DELETE succeeded and sends no body.

400

Bad Request

The JSON or the input is invalid.

404

Not Found

That student id is missing.

401 means sign-in is required. 403 means the caller may not do this. 409 means the request conflicts with current data. 500 means an unexpected server failure.

ResponseEntity

The method chooses the status and the body.

200

ok

ResponseEntity.ok(student) sends the student.

201

created

status(HttpStatus.CREATED).body(saved) sends the new student.

204

no content

noContent().build() sends a success with an empty body.

Returning a Student directly is enough for a first example. ResponseEntity also sets the HTTP status.

Create, update, delete

POST sends 201. DELETE sends 204.

StudentRestController
@PostMapping
public ResponseEntity<Student> createStudent(
        @RequestBody Student student) {
    Student saved = service.createStudent(student);
    return ResponseEntity.status(HttpStatus.CREATED).body(saved);
}

@PutMapping("/{id}")
public ResponseEntity<Student> updateStudent(
        @PathVariable Long id,
        @RequestBody Student student) {
    return ResponseEntity.ok(service.updateStudent(id, student));
}

@DeleteMapping("/{id}")
public ResponseEntity<Void> deleteStudent(@PathVariable Long id) {
    service.deleteStudent(id);
    return ResponseEntity.noContent().build();
}
