Process vs Thread

The process is the kitchen. A thread is one cook.

A process is the whole running program. Threads are workers inside it. Runnable is the job card a cook can follow.

Creating threads

Two ways. Prefer Runnable.

Extend Thread, or implement Runnable and pass it to a Thread. Then call start(). Runnable is preferred — your class can still extend something else.

class HelloThread extends Thread {
    public void run() {
        System.out.println("Hello");
    }
}

HelloThread t = new HelloThread();
t.start();
class HelloTask implements Runnable {
    public void run() {
        System.out.println("Hello");
    }
}

Thread t = new Thread(new HelloTask());
t.start();

start vs run

run() stays on main. start() hires a worker.

If you call run(), it is just a method. No new thread. start() creates the worker, then Java calls run() for you.

Worker a = new Worker("A");
Worker b = new Worker("B");

a.run();   // still main
b.run();   // still main

a.start(); // new thread
b.start(); // new thread
A on main B on main A on Thread-0 B on Thread-1

Remember

Call start(). Never call run() when you want a new thread.

Lifecycle

A thread moves through a few states

Keep this conceptual. You do not pick CPU cores. Java and the OS schedule the work.

NEW

Created. Not started yet.

RUNNABLE

Ready, or running on a CPU.

BLOCKED

Waiting to enter a lock.

WAITING

Waiting until someone wakes it.

TIMED_WAITING

Waiting with a time limit. Sleep.

TERMINATED

run() finished. Done.

Path: NEW → start() → RUNNABLE → maybe wait → TERMINATED

sleep

sleep() pauses. Then the next add runs.

Add 1 to 5. Wait one second after each add. 1000 means one second. Catch InterruptedException.

public class SleepDemo {
    public static void main(String[] args) {
        int sum = 0;
        try {
            for (int n = 1; n <= 5; n++) {
                sum = sum + n;
                System.out.println("Add " + n + " → sum = " + sum);
                Thread.sleep(1000);
            }
        } catch (InterruptedException e) {
            System.out.println("Sleep was interrupted.");
        }
        System.out.println("Done. Sum = " + sum);
    }
}
Add 1 → sum = 1 Add 2 → sum = 3 Add 3 → sum = 6 Add 4 → sum = 10 Add 5 → sum = 15 Done. Sum = 15

Remember

Sleep does not start a thread. It pauses the worker that is already running this loop.

1 + 2 + 3 + 4 + 5 = 15. You see each step.

join

Main waits. Then it prints the total.

A worker adds 1 to 5. Without join(), main prints too soon. Total is often 0. join() waits until the worker finishes.

public class JoinDemo {
    static int total = 0;

    public static void main(String[] args)
            throws InterruptedException {
        Thread t = new Thread(new AddOneToFive());
        t.start();
        t.join();
        System.out.println("Total: " + total);
    }
}

class AddOneToFive implements Runnable {
    public void run() {
        for (int n = 1; n <= 5; n++) {
            JoinDemo.total = JoinDemo.total + n;
        }
    }
}
Without join: Total: 0 With join: Total: 15

Remember

Start. Join. Then print. 1 + 2 + 3 + 4 + 5 = 15 only after the worker ends.
